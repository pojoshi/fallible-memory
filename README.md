# fallible-memory

A memory layer for AI agents that knows it might be wrong. Every fact carries a source, a confidence, a freshness window, a scope, and a sensitivity, plus an explicit policy for what happens when it goes stale, gets contradicted, or gets revoked.

**Stack:** Python 3.11+, FastAPI, PostgreSQL with pgvector and pg_trgm, a hybrid retrieval pipeline (vector + trigram fusion, metadata filters pushed into SQL), custom evals, pytest. A TypeScript browser playground lives in [`web/`](./web).

**Try it without installing anything:** the [browser playground](web/demo/index.html) (open the file, or see the GitHub Pages link once deployed). Drag the day slider and watch facts age.

## What it does

```python
from datetime import datetime, timedelta, timezone
from fallible_memory import MemoryService, ask

mem = MemoryService()                       # in-memory; pass PostgresStore for the real thing
t0 = datetime(2026, 1, 1, tzinfo=timezone.utc)

mem.write(subject="user", predicate="home_city", value="Manama", source_type="stated", now=t0)

# A weak guess, written under a differently formatted slot name, disagrees. It is recorded, not applied.
mem.write(subject="user", predicate="Home City", value="Dubai", source_type="inferred", now=t0 + timedelta(days=2))

print(ask(mem, subject="user", predicate="home city", now=t0 + timedelta(days=3)).text)
# I have two conflicting answers for home city: "Manama" (you told me this) and "Dubai" (I inferred this).
# I'm leaning towards "Manama", but which one is right?
```

What's actually going on under that:

- **Tags** every fact with source, confidence, freshness, and scope (`Fact` in `models.py`; base trust 90 / 75 / 50 for stated / tool-output / inferred)
- **Shows its work**: every answer carries an evidence line (source, dates, confidence)
- **Resolves conflicts instead of trusting whatever's newest**: a write supersedes an older, less-trusted fact (kept for audit) or gets stored as a disputed claim, and the agent asks
- **Expires facts on a schedule**, not on a guess: freshness windows by source and volatility, confidence decays past the window, derived at read time and never stored
- **Recognizes the same slot under different wording** via hybrid matching: embedding cosine + pg_trgm similarity
- **Forgets for real**: revoke erases the value and leaves a one-way marker that blocks re-learning it
- **Gates retrieval** by scope and sensitivity

Details: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Scenarios with real output: [`docs/FAILURE_TESTS.md`](docs/FAILURE_TESTS.md). Measurements: [`evals/REPORT.md`](evals/REPORT.md). The two-year thesis: [`docs/THESIS.md`](docs/THESIS.md).

## Quick start

```bash
pip install -e '.[dev]'
python examples/walkthrough.py      # the failure scenarios, narrated, offline
pytest                              # in-memory tests (Postgres tests skip without a database)
python evals/run.py                 # regenerates evals/REPORT.md
```

With Postgres (pgvector image) and the API:

```bash
cp .env.example .env                # set TOMBSTONE_KEY
docker compose up --build           # API on http://localhost:8000, docs at /docs
```

Or run the API directly:

```bash
DATABASE_URL=postgresql://user:pass@localhost/fallible TOMBSTONE_KEY=... \
  uvicorn fallible_memory.api:create_app_from_env --factory
```

The database needs the `vector` and `pg_trgm` extensions (created automatically if the role may create them). Without `DATABASE_URL` the API falls back to the in-memory store.

| Endpoint | Purpose |
|---|---|
| `POST /facts` | Write a claim; returns created / reconfirmed / superseded / disputed / rejected |
| `POST /retrieve`, `POST /ask` | Retrieve with confidence and history, or get the agent's behaviour (`assert`, `hedge`, `ask`, `unknown`, `withheld`); `/ask` accepts free text |
| `POST /search` | Hybrid search with metadata filters; returns the score breakdown |
| `GET /facts` | Memory inspector: what is remembered, how sure, and why |
| `POST /forget`, `POST /forget/scope` | Erase a slot, or everything in a scope |

## What is measured

`evals/REPORT.md`, generated by `python evals/run.py`, on a small hand-labelled set (28 same-slot pairs, 24 different-slot pairs, 26 queries) with the default offline hashing embedder:

- **Conflict detection when the slot is named differently:** 15/28 caught by hybrid matching vs. 1/28 by exact matching, with 0/24 different slots wrongly merged.
- **What it misses:** most true paraphrases (`employer` vs. `works_at`, `birthday` vs. `date_of_birth`), because the default embedder is lexical, not semantic. 3 of the 13 misses are at least flagged as a possible duplicate instead of silently ignored.
- The thresholds (0.70 merge, 0.55 uncertain) came from a sweep on this same small set, so treat them as a starting point, not a validated result. Semantic embedders (`EMBEDDER=st:...`, the `ml` extra) are supported but unmeasured here.

## Verified, and not

Verified: all 76 tests pass against a real PostgreSQL 16 + pgvector (35 run without a database, the other 41 need one and skip otherwise), including a concurrent-writer test, pg_trgm parity, and shared conformance fixtures run by both Python and the TypeScript playground (48 playground tests, 24 demo checks in jsdom). `docker compose up --build` builds and runs cleanly, with the API answering `/health`, `/facts`, and `/ask` against the containerized Postgres.

Not verified: the CI workflows (never run on GitHub) and the `st:` sentence-transformer embedder.

## Known limits

- Default embedder is lexical; paraphrase matching needs a semantic one and a larger labelled set to tune.
- Tombstones match slots, not meanings: a revoked fact can be re-learned under a name that doesn't clear the match threshold.
- Sensitivity is a keyword heuristic, not a classifier. No authentication: access context comes straight from the request body.
- TTLs, base confidences, and decay are hand-set, not learned. Revoke can't recall copies outside the store (logs, backups, model context).

More in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#known-limits).
